# リーグ戦シミュレーター

リーグ戦の星取表を入力すると、残り試合の**全結果パターン**を数え上げて、
「誰が何位以内に入れるか」「そのための条件は何か」を調べる静的Webアプリです。
ビルド不要・サーバー不要で、GitHub Pages にそのまま置けます。データはブラウザの localStorage に保存されます。

## 使い方

1. **設定** — 参加者と、試合結果の種類(勝ち・引き分け・無効試合など)と勝ち点を登録します。
   - 「勝敗が決まる」結果は勝者・敗者に別々の点が入ります(例: 勝ち 2点/0点)。
   - 「双方同じ点」の結果は両者に同じ点が入ります(例: 引き分け 1点)。
   - 「予測に含める」にチェックした結果が、未実施試合で起こり得る結果として数え上げの対象になります。
2. **星取表** — マスをクリックして消化済みの試合結果を入力します。現在の勝ち点順位も表示されます。
3. **シミュレーション** — 「n位以内(勝ち抜け)」または「ちょうどn位」を選んで計算します。
   - 各選手が条件を満たすパターン数・割合(確定 / 決定戦)
   - 順位ごとの分布
   - 決定戦が必要になる選手の組み合わせ
   - 「条件を見る」で、選んだ選手が条件を満たす未実施試合の結果の組み合わせを、同じ内容の行をまとめて一覧表示

### 同点の扱い

1. 勝ち点の多い順に並べます。
2. 勝ち点が同じ選手が複数いれば、その選手たちの間の直接対決だけで勝ち点を数え直して順位を付けます。
3. それでも同じ勝ち点が残る選手たち(三すくみなど)には、その選手たちの間でもう一度同じ判定をします。
4. どうしても順位が付かない場合は「決定戦が必要」とし、確定とは別に集計します。
   決定戦として数えるのは、決着のつかない範囲が狙う順位をまたぐ場合だけです(1〜2位が同点でも「2位以内」ならどちらも通過なので確定)。

### 計算量の目安

全パターン数は `(1試合の結果数)^(未実施試合数)` です。約 2,000万通りまでは全網羅し(端末により 50万〜100万通り/秒)、
それを超える場合はランダム抽出による確率の概算になります(条件の一覧は出せません)。
計算は Web Worker で行うので、計算中も画面は固まらず、途中で中止できます。

## インポート / エクスポート

右上の「インポート / エクスポート」から、表示中のリーグまたは全リーグを `.json` で保存・読み込みできます。
`_example/` にあるような次の形式のファイルも読み込めます。

- `participants: ...` / `scoring: ...` と `竹下 > 後藤` の行で書くテキスト形式
- `w / l / d / x` を並べた星取マトリクス形式の JSON

保存形式(人が読めて手で編集できます):

```json
{
  "app": "league-simulator",
  "version": 1,
  "leagues": [{
    "name": "Aブロック",
    "participants": ["竹下", "後藤", "ボルチン"],
    "outcomes": [
      { "id": "win",  "name": "勝ち",     "kind": "decisive", "win": 2, "lose": 0, "mark": "勝", "loseMark": "負", "simulate": true },
      { "id": "draw", "name": "引き分け", "kind": "shared",   "pts": 1, "mark": "分", "simulate": false }
    ],
    "matches": [
      { "a": "竹下", "b": "後藤", "outcome": "win", "winner": "竹下" },
      { "a": "後藤", "b": "ボルチン", "outcome": "draw" }
    ],
    "target": { "mode": "within", "n": 2 }
  }]
}
```

`matches` に書かれていない組み合わせは未実施として扱われます。

## GitHub Pages で公開する

1. このリポジトリを GitHub に push します。
2. リポジトリの **Settings → Pages** で、Source を「Deploy from a branch」、Branch を `main` / `/ (root)` にします。
3. 表示された URL を開きます。

`_example/` と `tests/` は公開に不要です(`.gitignore` で `_example/` は除外済み)。

## ローカルで動かす

`file://` で開くと Web Worker が使えず、計算が画面を止める形でのフォールバックになります。
ローカルサーバーを立てて開くのがおすすめです。

```bash
python3 -m http.server 8000
```

## テスト

```bash
node tests/engine.test.js
```

三すくみ・直接対決・小数点などの手計算できるケースに加え、`_example/league.js` がある場合は、
その出力(順位分布・決定戦の件数)と突き合わせます。

## 構成

| ファイル | 役割 |
| --- | --- |
| `index.html` | 画面の入れ物 |
| `css/style.css` | スタイル(ライト/ダーク対応) |
| `js/engine.js` | 数え上げ・順位決定・条件の圧縮(DOM 非依存。Worker / Node でも動く) |
| `js/worker.js` | 重い計算を別スレッドで実行 |
| `js/model.js` | リーグのデータモデル、保存形式、インポート |
| `js/app.js` | 画面と localStorage |
