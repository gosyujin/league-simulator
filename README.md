# リーグ戦シミュレーター

リーグ戦の星取表を入力すると、残り試合の**全結果パターン**を数え上げて、
「誰が何位以内に入れるか」「そのための条件は何か」を調べる静的Webアプリです。
ビルド不要・サーバー不要で、GitHub Pages にそのまま置けます。データはブラウザの localStorage に保存され、GitHub Gist で端末間・他の人と共有することもできます。

## 使い方

1. **設定** — 参加者と、試合結果の種類(勝ち・引き分け・無効試合など)と勝ち点を登録します。
   - 「勝敗が決まる」結果は勝者・敗者に別々の点が入ります(例: 勝ち 2点/0点)。
   - 「双方同じ点」の結果は両者に同じ点が入ります(例: 引き分け 1点)。
   - 初期設定: 勝ち(2/0点 ○/●・予測に含める)、引き分け(1点 △)、無効試合(0点 ─)、不戦勝(2/0点 ◻/▪)。引き分け・無効試合・不戦勝は予測に含めません。
   - 「予測に含める」にチェックした結果が、未実施試合で起こり得る結果として数え上げの対象になります。
2. **星取表** — マスをクリックして消化済みの試合結果を入力します。現在の勝ち点順位も表示されます。
3. **シミュレーション** — 「n位以内(勝ち抜け)」または「ちょうどn位」を選んで計算します。
   - 各選手が条件を満たすパターン数・割合(確定 / 決定戦)
   - 順位ごとの分布
   - 決定戦が必要になる選手の組み合わせ
   - 「条件を見る」で、選んだ選手が条件を満たす未実施試合の結果の組み合わせを、同じ内容の行をまとめて一覧表示

### 同点の扱い

1. 勝ち点の多い順に並べます。
2. 勝ち点が同じ選手が複数いれば、その選手たちの間の直接対決だけで勝ち点を数え直して順位を付けます。
3. それでも同じ勝ち点が残る選手たち(三すくみなど)には、その選手たちの間でもう一度同じ判定をします。
4. どうしても順位が付かない場合は「決定戦が必要」とし、確定とは別に集計します。
   決定戦として数えるのは、決着のつかない範囲が狙う順位をまたぐ場合だけです(1〜2位が同点でも「2位以内」ならどちらも通過なので確定)。

### 計算量の目安

全パターン数は `(1試合の結果数)^(未実施試合数)` です。約 2,000万通りまでは全網羅し(端末により 50万〜100万通り/秒)、
それを超える場合はランダム抽出による確率の概算になります(条件の一覧は出せません)。
計算は Web Worker で行うので、計算中も画面は固まらず、途中で中止できます。

## 静的HTMLとして保存

右上の「HTMLで保存」から、**その時点のスナップショットを、CSSも含めた1枚のHTML**として保存できます。
`.html` を開くだけで表示でき、GitHub Pages などにアップロードするだけで公開できます(外部ファイル・通信は不要。必要なJavaScriptもHTMLの中に入ります)。

1. 「狙う順位」(例: 以内(勝ち抜け) / 2位)を決めて「HTMLを保存」を押します。保存時に、全パターンの計算と各選手の「条件」の集計も行います。
2. 保存したHTMLには、上から順に次が並びます(閲覧のみ。編集や再計算はできません)。
   - **星取表**: その時点の星取表(勝ち点つき)
   - **シミュレーション**: 条件 → 「n位以内に入れる可能性」 → 各選手の「条件」(「条件を見る」のページ内リンクで移動。パターン数から全通りの星取表を表示) → 決定戦が必要になる組み合わせ(ある場合のみ)

注意:
- 全網羅できない(約2,000万通りを超える)ときは保存できません。残り試合が減ってから保存してください。
- 条件の表は、1人あたり3,000行までに切り詰めます(切り詰めた場合はページ内に注記が出ます)。
- 条件の表の「パターン数」を押すと、画面と同じように、その行に当てはまる全通りの星取表をポップアップで表示します。星取表はページを開いたときにその場で再現するので、HTMLには結果の組み合わせだけを埋め込んでいます(HTMLのサイズは条件の行数に比例します)。
- 保存には `css/style.css` と `js/` を読み込む必要があるので、ローカルサーバーかGitHub Pages経由で開いたアプリから保存してください(`file://` では保存できないことがあります)。

## インポート / エクスポート

右上の「インポート / エクスポート」から、表示中のリーグまたは全リーグを `.json` で保存・読み込みできます。
`_example/` にあるような次の形式のファイルも読み込めます。

- `participants: ...` / `scoring: ...` と `竹下 > 後藤` の行で書くテキスト形式
- `w / l / d / x` を並べた星取マトリクス形式の JSON

保存形式(人が読めて手で編集できます):

```json
{
  "app": "league-simulator",
  "version": 1,
  "leagues": [{
    "name": "Aブロック",
    "participants": ["竹下", "後藤", "ボルチン"],
    "outcomes": [
      { "id": "win",  "name": "勝ち",     "kind": "decisive", "win": 2, "lose": 0, "mark": "○", "loseMark": "●", "simulate": true },
      { "id": "draw", "name": "引き分け", "kind": "shared",   "pts": 1, "mark": "△", "simulate": false }
    ],
    "matches": [
      { "a": "竹下", "b": "後藤", "outcome": "win", "winner": "竹下" },
      { "a": "後藤", "b": "ボルチン", "outcome": "draw" }
    ],
    "target": { "mode": "within", "n": 2 }
  }]
}
```

`matches` に書かれていない組み合わせは未実施として扱われます。

## Gist で保存 / 共有

右上の歯車(⚙)ボタンから、リーグを GitHub の Gist に保存・読み込みできます(hateb-tycoon の同期と同じ作り)。

- **1つの Gist に、リーグ1件 = 1ファイル**(`league-simulator-<リーグid>.json`)。リーグが増えると、Gist のファイルも1つずつ増えます。
  中身はこのアプリのエクスポート形式(リーグ1件)に、リーグの id と更新日時を足したものです。
  名前が `league-simulator-*.json` でないファイル(他のアプリのもの)は無視し、書き換えも削除もしません。
- **ID を指定すれば読み込めます**。Gist の ID か URL を貼って「確認」を押すと、Gist にあるリーグの一覧が出ます。読み込みにトークンは不要です(ID を知っている人は誰でも読めるので、リーグの内容を見られたくない場合は ID を共有しないでください)。
- **トークンを設定すると書き込めます**。書き込み・作成・削除には、`gist` スコープの classic Personal Access Token が必要です(fine-grained トークンは Gist 非対応)。
  入力欄の横の「トークンを発行」から、スコープ選択済みの作成画面を開けます。トークンはこの端末の localStorage にだけ保存され、GitHub 以外には送りません。共有 PC では入力しないでください。
- 「Gistを作成」で、シークレット Gist を新しく作り(今ある全リーグを1ファイルずつ書き込み)、その ID を Gist ID 欄に入れます(トークンが必要)。インポート / エクスポート(ファイル)は、これとは別に従来どおり使えます。

**自動では同期しません。** ローカルと Gist を突き合わせた一覧に、リーグごとの状態が出るので、1件ずつ(または一括で)選びます。

**アップし忘れの目印と警告。** 最後に Gist と同じ内容だったリーグを端末に記録しておき、それと違うリーグ(編集したあと Gist に書いていないもの、まだ一度も Gist と突き合わせていないもの)があると、歯車(⚙)ボタンに赤い点が出ます。
その状態でページを閉じようとすると、ブラウザの確認が出ます。Gist ID を設定していないときは出ません。赤い点は、Gist のダイアログで「確認」して内容が同じと分かったとき、または書き込み・読み込みをしたときに消えます(通信はダイアログを開いたときだけです。Gist 側が別の端末で変わっていても、ここでは分かりません)。

| 状態 | できること |
| --- | --- |
| Gistのみ | 取り込む |
| この端末のみ | 書き込む |
| 内容が違う | Gistの内容で置き換える / この端末の内容で上書きする(どちらも確認あり。更新日時の新しい方を目安に表示) |
| 同じ内容 | (何もしない) |
| 読み込めない(Gist 側のファイルが壊れている) | この端末の内容で書き込んで直す |

「Gistから削除」は Gist のファイルだけを消し、この端末のリーグは残ります。

### Gist のファイル数の上限

GitHub の API で取得できるのは **1つの Gist につき300ファイルまで**です(それを超えると一覧が切り詰められ、全部を取るには `git clone` が必要になります)。
そのためこのアプリは、300ファイルに達する書き込みを断ります。他のアプリのファイルが同居していれば、その分も数えます。上限に近づいたら、別の Gist を作って分けてください。
また、API が返すファイル本文は1つあたり1MBまでですが、リーグ1件は数KBなので問題になりません。

## GitHub Pages で公開する

1. このリポジトリを GitHub に push します。
2. リポジトリの **Settings → Pages** で、Source を「Deploy from a branch」、Branch を `main` / `/ (root)` にします。
3. 表示された URL を開きます。

`_example/` と `tests/` は公開に不要です(`.gitignore` で `_example/` は除外済み)。

## ローカルで動かす

`file://` で開くと Web Worker が使えず、計算が画面を止める形でのフォールバックになります。
ローカルサーバーを立てて開くのがおすすめです。

```bash
python3 -m http.server 8000
```

## テスト

```bash
node tests/engine.test.js
node tests/gist.test.js
```

三すくみ・直接対決・小数点などの手計算できるケースに加え、`_example/league.js` がある場合は、
その出力(順位分布・決定戦の件数)と突き合わせます。
`tests/gist.test.js` は GitHub の API を偽のサーバーに差し替えて、読み込み・書き込み・作成・削除・差分の判定を確かめます(実際の GitHub には接続しません)。

## 構成

| ファイル | 役割 |
| --- | --- |
| `index.html` | 画面の入れ物 |
| `css/style.css` | スタイル(ライト/ダーク対応) |
| `js/engine.js` | 数え上げ・順位決定・条件の圧縮(DOM 非依存。Worker / Node でも動く) |
| `js/worker.js` | 重い計算を別スレッドで実行 |
| `js/model.js` | リーグのデータモデル、保存形式、インポート |
| `js/gist.js` | Gist の読み書きと、ローカルとの差分の判定(DOM 非依存) |
| `js/boards.js` | 「条件」の1行に当てはまる全通りの星取表を描画(画面と静的HTMLの両方で使う) |
| `js/app.js` | 画面と localStorage、静的HTMLの書き出し |
